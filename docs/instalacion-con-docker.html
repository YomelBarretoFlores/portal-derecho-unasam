Instalación del portal de Derecho

Todo lo que hay que hacer para dejar el sitio publicado y funcionando, incluidas las cargas de archivos. Escrito para quien lo instala por primera vez en un servidor propio.

Entrega Imagen Docker desde el repositorio Dentro PHP 8.4 · FrankenPHP · Laravel 13 Fuera PostgreSQL 14+ · volumen de archivos

¿Basta con ejecutar el Dockerfile?

Casi. La imagen trae la aplicación completa, pero hay tres cosas que por definición viven fuera de un contenedor.

Lo trae la imagen

No hay que instalar nada

  • PHP 8.4 con todas sus extensiones
  • El servidor web (FrankenPHP)
  • Las dependencias de Composer
  • Los estilos y scripts ya compilados
  • Las migraciones, que se aplican solas al arrancar
  • El contenido institucional inicial

No hace falta PHP, Composer ni Node en el servidor. Solo Docker.

Lo pone usted

Tres cosas, y sin ellas no funciona

  • Una base de datos PostgreSQL, creada y vacía
  • Las variables de entorno, sobre todo las de conexión y la cuenta de administrador
  • Un volumen persistente para los archivos que se suban desde el panel

Sin base de datos la aplicación no arranca. Sin volumen arranca, pero los archivos subidos se pierden en cada actualización.

Antes de arrancar

I

Base de datos PostgreSQL

Versión 14 o superior. Créela vacía y anote servidor, puerto, nombre, usuario y contraseña.

No importe ningún volcado ni cree tablas: las migraciones lo hacen en el primer arranque, y también cargan el contenido institucional del sitio.

II

La clave de cifrado

Genérela una vez, en cualquier equipo con openssl:

echo "base64:$(openssl rand -base64 32)"

Ese texto entero, con el prefijo base64:, es el valor de APP_KEY. No la cambie después: al cambiarla, todas las sesiones abiertas dejan de ser válidas.

III

La contraseña del administrador

La elige usted. Mínimo 12 caracteres, con mayúscula, minúscula, número y símbolo; si no los cumple, la cuenta no se crea.

Quien la reciba debe cambiarla desde el panel: aquí queda guardada como variable de entorno.

Las variables de entorno, una por una

Se pasan al contenedor con --env-file o desde el panel del proveedor. Las marcadas como obligatoria hay que rellenarlas; las fija ya vienen con el valor correcto y no conviene tocarlas; las opcional solo hacen falta en casos concretos.

Identidad del sitio obligatoria

APP_KEY
Clave con la que se cifran las sesiones y las cookies. Se genera una vez (véase arriba) y no se cambia nunca.
APP_URL
Dirección pública completa del sitio, con https:// y sin barra final. Con ella se construyen los enlaces y las direcciones de los archivos: si está mal, las imágenes y los PDF apuntan a ninguna parte.

Identidad del sitio fija

APP_NAME
Derecho UNASAM. Aparece en el título de la pestaña del navegador.
APP_ENV
production. Activa las optimizaciones y desactiva las herramientas de desarrollo.
APP_DEBUG
false. Nunca lo ponga en true en un sitio publicado: los errores mostrarían al visitante rutas del servidor, fragmentos de código y valores de configuración.
APP_LOCALE · APP_FALLBACK_LOCALE
es. Idioma de los mensajes del sistema.

Base de datos obligatoria

DB_HOST
Servidor de PostgreSQL. Si corre en otro contenedor de la misma red, el nombre del servicio.
DB_DATABASE
Nombre de la base de datos creada.
DB_USERNAME · DB_PASSWORD
Credenciales de acceso. El usuario necesita permiso para crear tablas: las migraciones lo hacen en el primer arranque.

Base de datos fija

DB_CONNECTION
pgsql. El portal usa PostgreSQL; no está probado con MySQL.
DB_PORT
5432, salvo que su servidor use otro.
DB_SSLMODE
require si el servidor exige conexión cifrada. Si PostgreSQL está en la misma máquina o red interna, puede ser prefer.
DB_PERSISTENT
false. Evita reutilizar conexiones entre peticiones, que con un servidor intermedio da problemas difíciles de diagnosticar.
PGCONNECT_TIMEOUT
10. Segundos que espera antes de rendirse al conectar. Evita que una base caída deje peticiones colgadas.

Cuenta de administrador obligatoria la primera vez

ADMIN_NAME
Nombre de la persona, tal como aparecerá en el panel.
ADMIN_EMAIL
Su correo institucional. Es el usuario con el que se inicia sesión.
ADMIN_PASSWORD
Contraseña inicial, con los requisitos de arriba.
Solo hacen falta en la primera instalación. Si el portal ya tiene una cuenta de administrador, el arranque lo detecta y no pide nada: la línea del registro será «Ya hay un superadministrador; no hace falta crear ninguno».

Sesión, caché y red fija

SESSION_DRIVER
database. Guarda quién ha iniciado sesión en la base de datos, no en el disco del contenedor. Es importante: con el valor anterior (file), cada actualización del portal expulsaba a quien estuviera editando, y perdía lo que llevara escrito.
SESSION_SECURE_COOKIE
true. La cookie de sesión solo viaja por HTTPS. Si el sitio se sirviera por HTTP sin cifrar, nadie podría iniciar sesión: ese es el efecto esperado.
CACHE_STORE
file. Caché de contenido dentro del contenedor. Es desechable: se reconstruye sola.
QUEUE_CONNECTION
sync. Las tareas se ejecutan en el momento, sin proceso aparte. No hay que levantar ningún worker.
LOG_CHANNEL · LOG_LEVEL
stderr y error. Los mensajes salen por la salida estándar para que los recoja Docker, y solo se registran errores reales.
TRUSTED_PROXIES
Desde qué direcciones se acepta la cabecera que indica la IP real del visitante y si venía por HTTPS. Si el portal está detrás de un nginx o un balanceador, ponga aquí su IP o su rango; si no, el sitio creerá que todas las visitas llegan por HTTP y generará enlaces rotos. Nunca ponga *: la aplicación lo rechaza.

Archivos: qué hace falta para que las cargas funcionen

Es la parte que hoy está desactivada y la que permitirá subir fotos, portadas y PDF desde el panel. Hay dos maneras y el portal admite las dos sin cambiar código.

Por qué viene desactivado

Un contenedor sin volumen pierde todo lo que escriba en cuanto se reinicia o se actualiza. Si las cargas estuvieran activadas, alguien subiría la portada de un número de la revista y desaparecería en la siguiente actualización, sin aviso y sin manera de recuperarla. Por eso MEDIA_UPLOADS_ENABLED se activa a mano, y solo después de montar el almacenamiento.

Opción A — recomendada

Volumen en el propio servidor

Si el servidor tiene disco, es todo lo que hace falta. Sin cuentas ni servicios externos.

  • Montar un volumen en /app/storage
  • MEDIA_DISK=public
  • MEDIA_UPLOADS_ENABLED=true

El enlace público que sirve los archivos lo crea el propio arranque. Incluya ese volumen en las copias de seguridad.

Opción B

Almacenamiento de objetos

Si prefiere no depender del disco del servidor. Vale cualquier servicio compatible con S3: MinIO propio, Cloudflare R2, AWS S3.

  • MEDIA_DISK=medios
  • AWS_BUCKET, AWS_ENDPOINT y credenciales
  • AWS_URL: dirección pública de lectura
  • MEDIA_UPLOADS_ENABLED=true

Variables de archivos

MEDIA_DISK
public para el disco del servidor, medios para almacenamiento de objetos.
MEDIA_UPLOADS_ENABLED
El interruptor. Mientras esté en false, los campos de subida aparecen desactivados en el panel y quien redacta solo puede pegar direcciones de imágenes alojadas en otro sitio. Póngalo en true cuando el almacenamiento esté montado y comprobado.
MEDIA_MAX_IMAGE_KB · MEDIA_MAX_PDF_KB
Tamaño máximo por archivo en kilobytes. Por defecto 5 MB para imágenes y 20 MB para PDF. Si los sube, revise también los límites de su servidor intermedio.
CSP_IMG_HOSTS
Dominios externos autorizados a mostrar imágenes, separados por comas. El portal bloquea por seguridad las imágenes de sitios no declarados: es lo que impide que alguien cuele contenido ajeno en las páginas. El dominio del almacenamiento de objetos no hay que ponerlo aquí, se deduce de AWS_URL.

Manuscritos de la revista opcional

La revista puede recibir originales de autores a través del sitio. Viene desactivado.

SUBMISSIONS_DISK
local guarda los manuscritos en storage/app/private, fuera del alcance de la web. Con almacenamiento de objetos, manuscritos y un bucket distinto y sin lectura pública.
SUBMISSIONS_ENABLED · SUBMISSIONS_PRIVACY_APPROVED · SUBMISSIONS_STORAGE_PERSISTENT
Los tres se ponen en true a la vez para abrir la recepción: que la función esté activada, que la declaración de privacidad esté aprobada, y que alguien confirme que el almacenamiento privado persiste.
Los manuscritos llevan nombre, documento de identidad y teléfono de los autores, y son trabajos inéditos. El portal rechaza guardarlos en un disco público, y solo se descargan desde el panel con sesión iniciada.

Para comprobar el almacenamiento, desde dentro del contenedor:

docker exec portal-derecho php artisan almacenamiento:verificar

Dice en qué modo está cada almacenamiento, si se puede escribir y leer de verdad, y nombra la variable concreta que falte. Lo que no puede comprobar es que el almacenamiento sobreviva a un reinicio: eso confírmelo subiendo un archivo de prueba desde el panel, reiniciando el contenedor y comprobando que sigue ahí.

La instalación, paso a paso

  1. Preparar el archivo de variables

    Un archivo de texto, una variable por línea. Mínimo indispensable:

    # portal.env
APP_KEY=base64:…generada con openssl…
APP_URL=https://derecho.unasam.edu.pe
APP_NAME=Derecho UNASAM
APP_ENV=production
APP_DEBUG=false
APP_LOCALE=es

DB_CONNECTION=pgsql
DB_HOST=servidor
DB_PORT=5432
DB_DATABASE=nombre
DB_USERNAME=usuario
DB_PASSWORD=contraseña
DB_SSLMODE=require

ADMIN_NAME=Nombre Apellido
ADMIN_EMAIL=persona@unasam.edu.pe
ADMIN_PASSWORD=mínimo 12, con mayúscula, número y símbolo

SESSION_DRIVER=database
SESSION_SECURE_COOKIE=true
CACHE_STORE=file
QUEUE_CONNECTION=sync
LOG_CHANNEL=stderr
LOG_LEVEL=error
TRUSTED_PROXIES=IP o rango del proxy

MEDIA_DISK=public
MEDIA_UPLOADS_ENABLED=false

    Ese archivo contiene contraseñas. Permisos restringidos y fuera de cualquier repositorio.

  2. Construir la imagen y levantar el contenedor

    git clone https://github.com/YomelBarretoFlores/portal-derecho-unasam.git
cd portal-derecho-unasam

docker build -t portal-derecho .

docker run -d --name portal-derecho \
  --env-file portal.env \
  -p 8080:8080 \
  -v portal-storage:/app/storage \
  --restart unless-stopped \
  portal-derecho

    O con Docker Compose:

    # compose.yaml
services:
  portal:
    build: .
    env_file: portal.env
    ports: ["8080:8080"]
    volumes: ["portal-storage:/app/storage"]
    restart: unless-stopped

volumes:
  portal-storage:

    El contenedor escucha en el puerto 8080, o en el que indique la variable PORT. Sirve HTTP plano: el certificado lo pone su proxy.

  3. Leer el registro del arranque

    Es el paso que ahorra todas las dudas posteriores:

    docker logs -f portal-derecho
    → APP_URL = https://derecho.unasam.edu.pe
→ Directorios de almacenamiento…
→ Preparando la aplicación…
INFO  Configuration cached successfully.
INFO  Running migrations.
→ Planes de consulta…
→ Contenido institucional…
INFO  Seeding database.
→ Usuario administrador…
Usuario superadministrador creado: persona@unasam.edu.pe
→ Iniciando FrankenPHP en el puerto 8080…
FrankenPHP started 🐘

    Si aparece este aviso, revise las tres variables ADMIN_:

    ⚠  NO se creó el usuario administrador.

  4. Comprobar que el sitio responde y tiene contenido

    /up debe devolver una respuesta correcta: es la comprobación de salud. Y la portada debe mostrar las cifras del programa, los accesos y la historia. Si sale vacía, la siembra no se ejecutó y el registro del paso anterior dice por qué.

  5. Entrar al panel y cambiar la contraseña

    En /admin, con el correo y la contraseña de ADMIN_EMAIL y ADMIN_PASSWORD. No hay ningún enlace al panel desde el sitio público: se entra escribiendo la dirección.

  6. Activar las cargas de archivos

    Con el volumen ya montado, comprobar y activar:

    docker exec portal-derecho php artisan almacenamiento:verificar

    Si todo sale en verde, cambie MEDIA_UPLOADS_ENABLED=true en el archivo de variables y reinicie el contenedor. Después suba una imagen de prueba desde el panel, reinicie otra vez y compruebe que sigue ahí.

    Hasta que se haga este paso, quien redacta contenido no puede subir fotos: solo pegar direcciones de imágenes alojadas en otro sitio, y en un dominio autorizado.

Después de publicar

QuéPor qué
Copia de seguridad de la base de datos Todo el contenido vive ahí: textos, comunicados, perfiles docentes, la revista. El contenedor es reemplazable; la base de datos no
Copia del volumen de archivos Una vez activadas las cargas, ahí están las portadas, los PDF y los retratos
Cambiar la contraseña inicial Queda guardada en el archivo de variables, legible para cualquiera con acceso al servidor
Actualizar git pull, reconstruir la imagen y reiniciar. Las migraciones se aplican solas; el contenido no se toca
